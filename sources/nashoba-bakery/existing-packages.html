1. Summary

  • We already have the strongest piece. HyperFrames and its skills cover authoring, a single quality gate (check --json: lint, runtime errors, layout, contrast), frame snapshots for review, timeline edits, undo history, and local tools for voice, transcription, background removal and colour grading.1,2,3 It is Apache-2.0 and very active (84.3k stars).1
  • The closest thing to our end state is OpenMontage. It runs inside Claude Code or Codex, goes research → proposal → script → scene plan → assets → edit → compose, and enforces human sign-off at proposal, script, scene plan, assets and publish. It also runs a self-review after every render and can use HyperFrames as its renderer.7 It does not write lessons back into its skills.7 Best use: copy its gate design and reviewer checks rather than run the whole system.
  • Feedback-to-skill learning has tools, but no finished product. Anthropic's skill-creator gives a draft → test → human review → improve loop with a review viewer that saves feedback to a file.10 Community "self-improvement" skills log lessons to a file and promote them into skills only after review.81 We still have to connect the two.
  • Our voice approach is already the right one. Record the founder first, clean locally (DeepFilterNet, MIT/Apache)57, cut fillers from word timestamps (hyperframes transcribe)2, and use Rhubarb Lip Sync to drive the cartoon founders' mouths from the recording.60 Keep cloning (Qwen3-TTS locally, Apache-2.0)46 for small pickups only.
  • The research pipelines are not usable for us. Paper2Video, Code2Video, TheoremExplainAgent, ViMax, MovieAgent and VideoAgent are academic, mostly have no human checkpoints, and either need large GPUs or depend on generated video.28–34 Two ideas are worth taking: Code2Video's planner → coder → critic split, and the render-then-look loop.
  • Biggest gap: argument quality. No package checks that each claim in a sell script is needed, proven, and traced to the call transcript. We will write this skill ourselves. It can draw on the Toulmin model and Minto's pyramid.42,38
  • Other gaps no package fills: a check that drawings are physically plausible to an expert viewer, a check that the script sounds like the founder, and a reliable automatic pacing critic. Gemini can review a whole cut, but its timestamps are only accurate to the second and it is a cloud service.44
  • Things to avoid: generated photoreal video for the main story (our first video showed that fake realism hurts trust, and more than half of consumers want AI video disclosed79). Also avoid Sora (its API shut down on 24 Sep 2026)77, Chatterbox (retired Aug 2026)47, and models whose weights are non-commercial: F5-TTS, MMAudio, CrisperWhisper, and BRIA RMBG, which is rembg's default model.48,66,55,74

4. Proposed human checkpoints

Four main gates and one light final check. They are modelled on OpenMontage's enforced gates (proposal, script, scene plan, assets, publish)7 and changed to fit our lessons, especially "record the voice first, then time the visuals to it".

G1: Brief and claims ledger

Agent prepares, founder approves. Framework parts: objective, audience, argument.

  • Agent produces: a one-page brief (sales stage: cold, warm, evaluating or post-pilot; the one action we want; the emotion; the main viewer and the other likely viewers, such as engineers), plus a claims ledger. Each claim gets four entries: why we make it, what it proves, its evidence (quoted line from the call transcript or research, with source), and its risk if wrong.
  • Founder decides: cut, keep or soften each claim; confirm the objective.
  • Borrowed from: OpenMontage's proposal gate7; Toulmin claim–grounds–warrant42; Minto's "answer first, three or four supports"38.

G2: Script and storyboard

Writer agent, then a separate critic agent, then founder.

  • Agent produces: the script in the founder's spoken style, timed at about 150 words a minute35, and storyboard frames as real HyperFrames stills (snapshot)2, so the founder sees the real style.
  • Critic report beside it: each claim maps to the ledger; a list of banned AI-sounding phrases; "does the narration repeat the screen?"; "would an expert believe this drawing?" (for example, camera angle against the object); hook in the first 30 seconds, where Wistia saw the biggest early drop39.
  • Borrowed from: OpenMontage script and scene-plan gates7; Code2Video's separate critic29.

G3: Voice takes

Founder records, agent cleans, founder picks.

  • Agent produces: a cleaned recording (DeepFilterNet)57, a word-timed transcript2, flagged fillers and stumbles, and a list of lines that changed from the script.
  • Founder decides: which takes to keep and whether any one-word pickup may use a clone.
  • Then automatic: visuals are timed to the approved audio, mouths come from Rhubarb60, and check --json must pass before G42.

G4: Rough cut

Agent renders and self-reviews; founder watches.

  • Agent produces: the full render; a contact sheet of one frame per beat; a self-review covering file checks, audio levels, frames at fixed points and subtitle checks (as OpenMontage does)7; optionally a Gemini pacing note44.
  • Founder gives notes, each tagged [this video] or [rule]. HyperFrames history lets the agent undo a change that made things worse2.

G5 (light): Mix and ship

  • Music ducked under the voice, loudness normalised70, licences logged for every track and sound. One final watch.

Where general feedback is written back into skills

  1. Capture: during any gate, a note tagged [rule] is appended to learnings.md with status pending, the gate it came from, and the target skill (brief, claims, script voice, direction, visual, sound). This follows the community self-improvement pattern, where promotion "never" happens automatically.81
  2. Retro after each video: for each pending rule, run skill-creator on the target skill. Add the rule and an eval case built from the mistake, run the old and new skill side by side, and the founder approves in the review viewer.10
  3. Promote or reject: approved rules move into the skill's SKILL.md or a reference file. Rules seen only once can wait for a second occurrence, as the skill-improver pattern advises.82
  4. Agent memory as a fallback: subagents can have a memory folder that loads at start.15 Use it for soft preferences; keep hard rules in skills so they are versioned and tested.
  5. Codex too: Codex reads the same SKILL.md format from .agents/skills and ships its own skill-creator.12 Skills written this way work in both tools.

Practitioner frameworks worth encoding in skills

  • Strategic narrative (Andy Raskin). Open by naming a big, relevant change in the world. Then show winners and losers, the "promised land", our capabilities as the way there, and proof.36 Fits "sell the problem" and teaser videos.
  • Great Demo (Peter Cohan). "Do the last thing first": show the end result first, then how to get there. Open with a "situation slide" that restates the customer's situation and checks it is still right.37 Fits personalised follow-ups and proof-of-concept videos.
  • Pyramid principle / SCQA (Barbara Minto). Situation → complication → question → answer, with three or four supports under the answer, each answering "why?" or "how?".38 Fits the claims ledger and chapter order.
  • Explainer order. Hook → problem → solution → how it works → one call to action. Keep the problem setup short (one guide says under 15 seconds) and make the ask specific and easy.35 Narration runs at about 130–160 words a minute, so time it by reading aloud.35
  • Length and hook data (Wistia). In Wistia's 2016 study of 564,710 videos, 2 minutes was the "sweet spot". Their retention analysis shows a 4.9% early drop for 1–2 minute videos against 17.3% for 5–10 minute videos.39 Their 2024 report found little difference between 1 and 5 minutes, but a significant drop after 5.40

Gap: none of these tools links a claim to a line in the client's call transcript. That traceability is the core of our "credible, personalised, every argument thought through" rule, so the claims-ledger skill is ours to write.

5.6 Voice: founder's own voice, cleanup, cloning, lip-sync

Recording and cleanup (founder's own voice)

  • Recording. Sit 6–12 inches from the mic. Pick a soft, furnished room away from the street. Turn off humming devices. Read the script from a screen, not paper. Warm up by reading it aloud once.59
  • Noise removal: DeepFilterNet. Code and weights are MIT/Apache; it offers a real-time build and a binary with no Python.57 Local.
  • Fillers: hyperframes transcribe (Parakeet or whisper) gives word timestamps.2 CrisperWhisper writes fillers verbatim ("[um]") with word timing, but its weights are non-commercial, so commercial use needs a paid licence.55
  • Silences: auto-editor cuts silent parts by loudness (public domain, 5.9k stars).56
  • Manual option: Descript has one-click filler removal and Studio Sound. Its prices differ between sources.58 Cloud.

When generated video fits B2B credibility

  • Our own test: a photoreal composite of the founders was rejected; cartoon founders on a real storefront photo were accepted (framework notes).
  • The IAB 2026 study found more than half of consumers want AI video and images disclosed. The gap between how executives and consumers feel about AI ads grew from 32 to 37 points between 2024 and 2026.79 A 2026 study reported that ads labelled "AI assistance and human supervision" did better than "fully AI-generated".79 No B2B-specific study was found.
  • Rule for the visual skill: real photos of the client's site, plainly drawn or cartoon people, and diagrams. Generated clips only for abstract filler shots, never anything that claims to show the real floor.
5.9 Human-in-the-loop and orchestration (brief)

How existing tools structure approval

  • OpenMontage: gates are enforced in code. The checkpoint writer rejects a gated stage marked complete without a recorded approval, and old checkpoints are archived. Assets are approved on a scene-by-scene contact sheet showing cost and quality scores. A local board shows what is waiting.7
  • ViMax: a Web UI with named projects, storyboard previews and render checkpoints, plus session resume.31
  • FilmAgent: each stage can be viewed, edited and regenerated.32
  • skill-creator: a review viewer with per-case feedback that saves to feedback.json.10

Claude Code building blocks

  • Skills: one skill per stage. disable-model-invocation: true stops Claude from starting a stage on its own; context: fork runs a stage in a subagent; skills can bundle scripts and references.14
  • Subagents: separate writer and critic agents, each with preloaded skills, a chosen model, and an optional persistent memory folder.15
  • Hooks: UserPromptSubmit and Stop run on every turn and could, for example, prompt "log any [rule] notes" before a turn ends.16
  • LangGraph, in one line: interrupt() saves graph state and waits for a human to resume with input.80 We do not need it, because files and skill stages already give us that pause.

Capturing general feedback into skills

  • skill-creator loop: draft → run with and without the skill → grade → human review → improve. It warns against over-fitting to a few examples ("skills that can be used a million times").10
  • Self-improvement skills: log to .learnings/ with status pending, promoted or won't-fix; promotion into CLAUDE.md, AGENTS.md or a skill is manual.81
  • Skill-improver pattern: reads saved feedback files and changes SKILL.md only when a pattern repeats across sessions.82
